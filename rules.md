## Comment Rules

- Comments explain why: design rationale, data-processing assumptions, external constraints, non-obvious tradeoffs, or domain rules that code cannot express by itself.
- Do not write comments that merely repeat the code, such as "calculate average" before an average calculation.
- Do not write change-history comments. Avoid phrases such as "fixed", "updated", "NEW", "as requested", "per user request", or "changed from X to Y".
- Put change history in commit messages, pull requests, or release notes.
- When code changes, update or delete stale comments in the same change.
- If a comment is only useful during the editing session, do not commit it.
